# September 17, 2026 - Multiple authenticators, folder and app fixes, and server reliability

Here is a summary of changes shipped since our [last product update](/release-notes/command-deck/2026-09-03).

## Account security

- You can now enroll more than one authenticator app on your HexOS account from the **Security** pane. Each authenticator gets a device name so you can tell them apart, and **Make primary** lets you choose which one confirms sensitive changes.
- In some cases, accounts with more than one authenticator could not change their password: a code from any authenticator other than the oldest one was rejected as incorrect. Password changes now verify against your primary authenticator, and the error message explains what to do if a code is rejected.
- The password form now asks for your verification code up front when an authenticator is enrolled, instead of reporting a wrong password after the fact.
- Password managers such as 1Password and LastPass no longer offer to save folder encryption passphrases, unlock passphrases, or TrueNAS user passwords. Your HexOS login is still offered for saving as usual.

## Folders

- Folder sizes now reflect the files in the folder. Space still held by restore points is shown separately on the folder page, and sizes refresh shortly after you copy, move, delete, or upload files. Previously, a folder could report the same size after a large delete because restore points still held the deleted files.
- In some cases, editing a folder that contained a TrueNAS app's data failed with a generic error, even for a change as small as a quota. These edits now succeed, and when app data does conflict with folder permissions, the message explains the conflict.
- In some cases, a folder edit that failed partway left the folder's network share switched off with nothing on screen to explain it. The share now comes back online whenever it is safe to do so.
- The folder encryption help link now opens the correct section of the documentation.

## Apps

- The dashboard now shows the name you gave a TrueNAS catalog app when you installed it, instead of the catalog's default title. Apps installed under their default name are unchanged.
- In some cases, an app install or update failed with a message about a missing folder when the real cause was a damaged app catalog on the server. Command Deck now names the cause, repairs the catalog automatically, and keeps a copy of the damaged one aside.
- The **Update all** confirmation now shows the app version and the TrueNAS catalog version side by side with arrows, and marks a version that is not changing as unchanged.
- App update cards now show the day each update was found in your server's timezone and in your locale's date format. Duplicate cards for the same day are folded together, dismissed cards no longer come back on their own, and only the newest update card is pinned above other messages so a critical alert is never pushed down the list.

## Storage

- Pools created in TrueNAS with layouts HexOS does not build itself, such as dRAID or pools with cache, log, or special devices, are now described accurately. A distributed spare taking over no longer appears as a removed drive, a layout HexOS does not recognize reads as "Layout not recognized" rather than as unprotected, and a hot spare covering a special or log mirror is now promoted like any other spare.
- In some cases, a pool whose root dataset is mounted somewhere other than the default location showed a blank capacity card. Capacity is now read directly from the pool.
- Drives that report themselves as failing are no longer offered or accepted as hot spares.
- In some cases, a drive much smaller than a pool's members could be offered as a hot spare for a degraded pool. Hot spare sizing now considers only the pool's data drives.
- When a drive cannot be used as a hot spare, Command Deck now tells you why: the drive is failing, it is the wrong type, it is too small, or the pool layout does not support spares.

## TrueNAS updates

- New TrueNAS stable releases now appear in Command Deck once the HexOS team has verified them, rather than the moment TrueNAS publishes them. Releases already verified continue to be offered as before.
- In some cases, servers running a TrueNAS pre-release were not offered newer pre-releases on the same train. They are now.

## Memory testing

- Memory testing is now available on servers running as virtual machines. The confirmation dialog explains that the test covers the memory assigned to the virtual machine rather than the host's physical RAM.
- In some cases, the green **PASS** banner appeared after the first clean pass. Anyone reading it as the end of the test pressed Esc and returned to a run that HexOS reported as cut short. The banner now appears only once the final pass completes.
- A memory test no longer starts while long-running work that its reboot would interrupt is in progress, and that work waits while a memory test reboot is pending.

## File browser

- Pressing Enter in the **New folder** or **Rename** dialog no longer opens a second, empty dialog after completing the action.

## Setup and recovery

- In some cases, when a server rebooted and its drives took a while to appear, automatic recovery could move the app configuration to a different pool and hide your installed apps. Recovery now waits for the original pool to come back and shows why it is waiting.
- The hosted mode and reconnect banners no longer appear over the setup wizard, where neither had anywhere to send you.

## Reliability

- In some cases, on internet connections that only pass smaller packets, everyday requests worked but every self-update download failed. Servers now detect this condition on their own and adjust.
- In some cases, the server switcher showed "Online: attention needed" while the dashboard reported a healthy server. The two now agree.
- In some cases, a brief connection interruption between your server and HexOS showed a full-screen "server not available" message even though the connection restored itself within seconds. Command Deck now waits out short interruptions before changing your server's status.
- In some cases, a server reconnecting after a dropped connection was refused because HexOS still considered the old connection alive, leaving the server showing as offline or reachable only on your local network. A fresh connection now replaces the stale one right away.

**NOTE:** All of these updates are applied automatically to your Command Deck. You may need to clear your cache. Help with clearing your cache is available [here](/troubleshooting/browser-cache).
