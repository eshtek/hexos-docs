# August 27, 2026 - ZFS pool import, Update all, and server reliability

Here is a summary of changes shipped since our [last update](/release-notes/command-deck/2026-08-24).

## ZFS pool import

- The setup wizard now detects existing ZFS pools and imports them with data intact, instead of suggesting those drives for new pools
- When imported pools are present, setup defaults to keeping them and walks you through a review of inherited pools, folders, apps, and Time Machine backups
- Folders on imported pools whose SMB shares were lost can be restored as HexOS folders, including Time Machine shares and passphrase-locked datasets
- Pools can also be imported from the storage page after initial setup
- Drives belonging to imported pools are protected from being reused in new pool suggestions

## Apps

- Update all is now available on the Installed apps screen, so you can apply every pending update in one action
- Apps under maintenance are automatically excluded from Update all to prevent interruptions

## Setup

- In some cases, the adoptable folders notice could overlap with the folder list. It now appears below the folders with a dismiss action.
- Server errors during password changes are now surfaced clearly on the form instead of appearing as a validation error on the current password field

## Reliability

- In some cases, a server could appear unreachable in Command Deck even though TrueNAS was running. Command Deck now detects and recovers lost middleware sessions automatically.
- Command Deck updates now apply cleanly without requiring a manual page refresh. In rare cases, browsers could cache an older version of the interface after an update.

**NOTE:** All of these updates are applied automatically to your Command Deck. You may need to clear your cache. Help with clearing your cache is available [here](/troubleshooting/browser-cache).
