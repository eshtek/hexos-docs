# October 6, 2026 - Pool repair tools, Repair access for folders, and a date format setting

Here is a summary of changes shipped since our [last update](/release-notes/command-deck/2026-10-02).

## Storage

- **One-click Repair for damaged files.** When ZFS reports data errors, Command Deck now identifies the affected files and offers a **Repair** action that removes them. For damaged TrueNAS catalog files, the repair targets only catalog data: no user files are involved, and the catalog rebuilds on its own.
- **Check pool and Reset error count.** Two new pool actions let you verify a pool's integrity after a repair and clear the error count once the issue is resolved. If a repair cannot proceed, the reason is explained.
- **Missing apps drive screen.** When the drive holding your apps goes missing after a restart, a dedicated screen shows the drive to look for and offers a **Shut down server** button so you can check the connection safely. If a restart does not bring the drive back, a warning explains the next step.
- A missing pool drive now shows its serial number, model and size, so you can identify which physical drive needs attention.
- In some cases, a restore or pool move that stopped on an unreadable block did not record the damage. The affected folder's damage is now tracked and surfaced.

## Folders

- **Repair access.** After a pool rebuild or restore, a folder's network accounts can lose effective access: the share connects, but files appear empty or show "Permission denied." Saving the folder now repairs its own directory. For deeper issues across many files, a new **Repair access** action scans every file and restores the correct permissions, with progress shown in real time.
- In some cases, reopening the Edit Folder dialog after a save showed each user's access as it was first loaded. Saving from it could revert a recent change. The dialog now reflects the current access levels.
- In some cases, share permissions left behind by deleted local accounts could prevent TrueNAS 24.10 from reading the share. Saving the folder now cleans up those stale entries.
- The **Lock** tile no longer appears for shares that unlock with another dataset's key.

## Folder encryption

- **Smarter space estimates.** The Turn on encryption dialog now shows only the space the conversion needs, not the pool's total headroom. On large pools, the estimate is dramatically more accurate.
- **More reliable conversions.** File-by-file encryption now moves files in batches that fit the available space and handles folders near their size limits without running out of quota. Dangling symlinks no longer stop a conversion. Failed moves that have not transferred any files can be discarded, and every blocker now explains what it is and what to do next.

## Apps

- **Secrets preserved during updates.** App updates now keep live passwords, keys, and environment secrets that the install script would otherwise regenerate. Update logs mask sensitive values.
- In some cases, a failed app upgrade continued to appear at the top of the app's detail pane after the app upgraded successfully. The failure now clears once the upgrade completes.
- In some cases, a run-once app action could not run again after reinstalling the app. Run-once actions now reset on reinstall.

## Date format

- **Choose how dates appear.** A new setting beside the temperature unit lets you choose how dates are displayed throughout Command Deck. Every date, timestamp, and relative-time label follows the format you pick.

## Dashboard and file browser

- The **Backups** section on the dashboard can now be hidden from its own menu or from **Customize dashboard**.
- File browser delete, rename and move no longer affect shared folders, nested datasets, or paths outside the selected folder. Shared folders nested inside other shared folders are protected from accidental changes.

## Reliability

- In some cases, error messages from the server were replaced by a generic offline page on deck.hexos.com. Server errors now reach Command Deck with their specific message.
- A server caught in a restart loop now names the cause and links to a troubleshooting guide.
- In some cases, a server installed from a legacy BIOS boot could not run the memory test. Command Deck now explains why and describes the path to UEFI, where the full test is available.

**NOTE:** All of these updates are applied automatically to your Command Deck. You may need to clear your cache. Help with clearing your cache is available [here](/troubleshooting/browser-cache).
