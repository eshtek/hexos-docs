# November 20, 2026 - Automatic Ripping Machine, Plex apps away from home, your own ISOs, and more

Here's what shipped since our [last update](/release-notes/command-deck/2026-11-17).

## New curated apps

- [Automatic Ripping Machine](https://github.com/uprightbass360/automatic-ripping-machine-neu) - Put a Blu-ray, DVD or CD in your server's disc drive, and it gets copied to your server. With Radarr and Sonarr connected, each movie and episode is named, filed in your library and ready to watch.

## HexOS Anywhere

- **Plex apps away from home.** Away from home, Plex's TV and phone apps would show your server as unavailable, even though its Anywhere address opened in a browser. Plex now gives plex.tv its Anywhere address, so the apps find your server wherever you are. While Plex has an Anywhere address, Plex's own **Remote Access** and **Relay** are turned off.
- **OpenCloud at its Anywhere address.** When you turned on OpenCloud's Anywhere address, OpenCloud would answer **Missing or invalid configuration**, and its phone and desktop apps couldn't sign in. Click **Use its Anywhere address** to move OpenCloud there. After that, **Launch** opens the Anywhere address at home too.
- **Your own proxy doesn't need Anywhere.** When you served the Command Deck through a reverse proxy of your own, signing in at that address would fail unless the server had HexOS Anywhere. That sign-in now works without it. HexOS Anywhere is only needed for addresses that go through the HexOS relay. The Command Deck card in **Settings** > **Anywhere** takes your proxy's full HTTPS address again.
- With Pi-hole or AdGuard Home installed, the note under the direct connection switch in **Settings** > **Anywhere** now names the app that manages your DNS. It also gives the address to set as the primary DNS server in your router.

## Virtual machines

- **Add your own ISO.** A server has no Install Media folder until its first VM is installed. Before, the **Choose an ISO** list in **Set up a Custom VM** would open empty on a server like that. The ISO list now ends in an **Add ISO** row, and the **Installed VMs** page has a **Manage ISOs** button. Both open the file browser at Install Media, where you can upload an ISO or pick one. If the folder doesn't exist yet, HexOS asks before it creates it.
- **Downloads pick up where they left off.** When a connection dropped or went quiet during a download, the whole download would fail, and the partial file was deleted. A large installer ISO could never finish on a flaky connection. Installer ISO downloads and **Download from URL** in the file browser now resume from where they stopped, when the site allows it.
- On TrueNAS 25.04.0 and 25.04.1, which have no virtual machine support, the **Virtual machines** page would show errors. The drive list in **Bring over** would fail to load too. Both now load normally.

## Buddy Backups

- **Clearer removal notices.** When a buddy removed a backup connection, you would get a notice saying the backup "was removed and its data deleted from this server". Only the copy on your buddy's server gets deleted, so the notice could make you think your own files were gone. Each server now gets its own notice, and yours says your files and restore points weren't touched.
- The server that stores a backup now also gets a notice when the source server is reset or unclaimed.
- **Verify your email to see invites.** Buddy Backup invites show only for an account with a verified email. When an account wasn't verified, its **Incoming requests** list would just be empty. A notice now explains why, and its **Send verification email** button sends the email.

## Apps

- **Real names on your server's home page.** The page at your server's own address would show custom apps as "iX App" with TrueNAS's generic icon. It now shows each app's own name and icon.
- In some cases, an install step that wrote into a folder made by the same install would fail. Pi-hole's **Keeping Pi-hole's DNS on this server's own address** step was one of them, and a retry lost the folders. These steps now find their folders.
- When other apps also had updates waiting, HexOS would never update itself, and its **Update available** badge stayed. HexOS now updates itself either way.
- Optional install questions now say **(optional)** after their label, so you know you can leave them blank.
- New Minecraft installs start with a setting that protects the server from the Java4Shell vulnerability (CVE-2026-114938).
- Stardew Valley has screenshots, and its card shows a picture of the farm while someone is playing.

## Folder encryption

- When you reinstalled TrueNAS, your server came back under a new identity, and the Command Deck would show **Recovery key not ready yet**. Your recovery key now moves to the reinstalled server once the server proves it holds the key.

## Help and security

- We tightened security checks across sign-in, claiming a server, two-factor settings, Buddy Backups, HexOS Anywhere and the connection between your server and HexOS Cloud.

**NOTE:** These updates apply automatically. You may need to [clear your cache](/troubleshooting/browser-cache).
