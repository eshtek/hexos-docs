¶ Contribute to the documentation

You can help by reporting a problem, correcting an existing page or writing a guide. Read the style guide and documentation license before contributing text or images.

¶ Report a problem

Join the HexOS Discord Community and use the #Docs channel. Include the page link, the step that needs attention, what you expected and what happened. Include your HexOS or TrueNAS version when it affects the instructions. Keep passwords and personal information out of screenshots.

¶ Get editing access

Ask the documentation team for editing access and explain the page or guide you want to work on. Wait for access to be granted, then sign in to the documentation site. If the editing controls are missing, confirm your access with the team before continuing.

¶ Edit an existing page

Open the page and click Edit Page, the pencil control. The editor opens with the page's current contents.

Page editing and new-page controls

Make the correction in the Markdown editor. Check the preview alongside it. Keep the page's address and community credits unless the documentation team agrees to change them.

Click Save, the checkmark control at the top, and wait for Saved. Click Close to return to the page and check the saved result.

Markdown editor and save control

Warning: Do not assume an unsaved edit is protected. Save explicitly and check the result before closing the editor. Saving a published page updates that page; arrange review before making a substantial change to it.

Tell the documentation team which page you changed and what you checked.

¶ Create a community guide

Describe your proposed guide in #Docs before starting. Agree on its subject and location so it does not duplicate an existing guide.

¶ Choose the page address

Click New Page, the page-with-plus control at the top of the site. In Select New Page Location, enter the agreed path. Community guides normally use community/community-guides/ followed by a short lowercase name with hyphens, such as my-guide. Do not include a leading or trailing slash in the path field.

New page location

Click Select. The next screen asks which editor to use. Click Markdown so the guide can use the callouts and screenshot markup in the style guide.

Markdown editor choice

¶ Set the title and description

In Page Properties > Info, enter the page's Title and a one-sentence Short Description. Use the same title for the first heading in your Markdown. The path is the page address; it does not need to match the title's capitalization.

Page title, description and path

¶ Keep the draft unpublished

Open Scheduling and turn Published off. An unpublished page is still visible to people with write permission for that page, so it is not a place for secrets. Click OK to return to the editor.

Published switched off

Write the guide and add screenshots using the style guide. Include the starting point, every action, the expected result and a way to check success. Credit the people whose work informed the guide.

Click Create to save a new page. Later edits use Save. Wait for the saved result, then reopen the page to check its text, links and images.

¶ Review and publication

Share the unpublished page link with the documentation team and ask for review. Keep Published off until the guide is approved. Review should include following the steps on the stated software version and checking every screenshot at full size.

Fix missing steps, broken links and outdated images before requesting publication. A documentation administrator can arrange publication and add the guide to the Community guides list.
